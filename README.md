# NewRail — журнал локомотивов

Цифровой паспорт локомотива: узлы, история обслуживания и ремонтов, неисправности с фотографиями и QR-код для быстрого доступа к карточке машины.

**Демо:** https://newrail-project.github.io/rail-hackathon/

## Возможности

- **Паспорт локомотива.** Узлы подбираются по типу машины (электровоз или тепловоз). У каждого узла — состояние, последнее ТО или ремонт, пробег, примечание и история изменений.
- **Место поломки.** Выбор узлов кнопками в анкете приёмки и в паспорте.
- **Фото.** Снимки неисправностей сжимаются в браузере и хранятся в Firestore, отдельный Storage не нужен.
- **Ремонт.** 18 стадий: от дефектовки до выдачи, плюс статусы «ожидает детали» и «приостановлен».
- **QR-код.** Ведёт на карточку конкретного локомотива: `…/?loco=ID`.
- **Удаление паспорта** с подтверждением номером. Каскадно удаляются ремонты, задачи, история, узлы, ИИ-анализы и фото.
- **Роли «Заказчик» и «Депо»** переключаются в шапке. Это демо-режим без входа.

## Структура

```
index.html                 разметка и логика приложения
css/style.css              базовая тема и элементы
css/newrail-adapter.css    шапка, семафор, модальные окна
css/ui.css                 выпадающие списки, диалоги, фото, мобильная адаптация
firestore.rules            правила доступа к Firestore
firebase.json              конфигурация деплоя
```

## Запуск локально

```
python3 -m http.server 8000
```

Открыть `http://localhost:8000`.

## Firebase

Проект: `rail-hackathon-db`. Конфигурация (`apiKey` и остальное) лежит в `index.html`. Это публичные данные Firebase, их можно хранить в коде. Защиту обеспечивают правила Firestore.

Деплой правил и сайта:

```
firebase deploy --only firestore:rules,hosting
```

## Искусственный интеллект

Анализ неисправностей использует сервис Pollinations без ключа. Если в Firestore сохранён ключ Groq (коллекция `settings`, документ `ai`, поле `key`), приложение использует его как запасной вариант. Ключ вводится через роль «Депо» → «ИИ-ключ» и в код не записывается.

## Важно перед боевым использованием

- Правила Firestore сейчас демонстрационные: данные открыты на чтение и запись, входа нет. Для реальной работы нужны авторизация и роли.
- Коллекция `settings` доступна на запись любому посетителю, а ключ ИИ лежит в ней. Для продакшена ключ нужно перенести в серверную функцию-прокси, а правила ограничить.
